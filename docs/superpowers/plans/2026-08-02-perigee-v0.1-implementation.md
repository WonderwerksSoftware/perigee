# Perigee v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Polaris-first Linux client based on current Moonlight Qt with a Search Rail Deck that is reachable by keyboard, mouse, and controller, performs every specified local and host action truthfully, and switches the active Polaris display through a verified reconnect-and-rollback transaction.

**Architecture:** Preserve Moonlight's stream engine and add a focused `app/perigee` layer. QML is rendered offscreen with `QQuickRenderControl` into Moonlight's existing overlay compositor; a pure action registry separates presentation from local and Polaris adapters; an input router owns Deck focus and neutralizes host input; a worker-thread HTTPS client reuses Moonlight's paired identity. The sibling Polaris fork exposes only the missing authenticated command acknowledgement, clipboard limit, and per-client output-selection contracts.

**Tech Stack:** C++17 and Qt 6.7+ (Qt Quick, Qt Network, Qt Test), QML, SDL2/SDL3 compatibility APIs, Moonlight Common C, qmake, C++23 Polaris, CMake, GoogleTest, nlohmann JSON, GitHub Actions, linuxdeploy/AppImage.

## Global Constraints

- Linux x86_64, Nobara, KDE Plasma, and native Wayland are the v0.1 release target. Keep new interfaces portable, but do not expand this plan into Windows or macOS qualification.
- Preserve Moonlight streaming, pairing, decoder, audio, controller, motion, rumble, and ordinary Sunshine behavior when Deck is closed.
- Keep Moonlight upstream as `moonlight-upstream`; keep the Perigee GitHub fork as `origin`. Do not rewrite upstream history.
- Keep Polaris upstream as `polaris-upstream`; implement server work in the sibling checkout `/home/wcfox/Documents/Codex/perigee-polaris`.
- Use Qt 6.7 or newer. Do not retain Qt 5 conditionals in new Perigee code.
- Deck must never be a second top-level window. Render QML offscreen and submit an ARGB surface through `OverlayManager`.
- Do not add a free-form shell endpoint. Named commands are selected by current server index, reauthorized at execution time, and acknowledged only after the child process is successfully spawned and detached.
- Do not log clipboard payloads, private keys, client certificates, session tokens, or request bodies. Test those redaction boundaries.
- Use test-first order in every behavior task: write one focused failing test, run it and observe the intended failure, implement the smallest passing change, rerun the focused test, then run the relevant suite.
- Never report a remote action as successful solely because a request was sent. Require local readback, Polaris readback, or an explicit authenticated acknowledgement defined by the contract.
- Do not publish releases, merge pull requests, or modify the live Polaris host until the user explicitly chooses that step. Local forks, commits, test builds, and artifacts are in scope.
- After every task, leave both repositories clean and make the named commit. If unrelated user changes appear, preserve them and commit only task-owned paths.
